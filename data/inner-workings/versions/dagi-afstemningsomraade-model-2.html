DAGI Afstemningsområde — domain model 2.0.0

DAGI Afstemningsområde — domain model 2.0.0

Nov 26, 20268 min read

In production since 2026-07-02 (the new administration system DAGI3); its data carry the register’s history back to 2018-03-05, migrated on 2026-07-01 (SystemMigreringDagi3). Conforms to DAGI domain model 2.0.0, class Afstemningsområde — geografisk inddeling af kommunerne i områder, hvor vælgere stemmer til Folketings-, EU- og Kommunevalg, samt til folkeafstemninger.

Two time axes, in practice

Every version of a polling district carries valid time (virkningstid: when it holds in the world) and registration time (registreringstid: when the register recorded it), each with the actor responsible, plus the business event (forretningshændelse) and process that caused the change. Datafordeler’s GraphQL API answers the bitemporal question directly: what did the register, as it stood at R, say was valid at V?

One rural district, Ejer Bavnehøj (700784, Skanderborg), asked at five valid times (rows) as the register stood at five registration times (columns). Each cell: the version returned, as valid from / registered.

Read along a row: the same moment in the world, as the register knew it at different times. In the 2024-01-01 row the answer changes between mid-2024 and mid-2025 — a correction registered on 2024-10-03 closed the version’s validity retroactively. The 2026-07-01 column change is a system migration (SystemMigreringDagi3, event Fejlrettelse) that re-registered 413 districts at once. Read down the first column: as the register stood in 2019, nothing after 2018 existed — obviously, but it is what makes an analysis on an old extract reproducible.

For this district every version has the same area (60.3109 km²); only the number of vertices changes (1 197 → 1 441 → 1 437) — map-matching to GeoDanmark (FOTAjourføring) and corrections, not redistricting. Most versions are not changes in the world. The event field is what tells the two apart.

A student who joins election results across years by name and number would join two different areas; one who joins by id_lokalId would see a break where the name suggests continuity. The model records identity explicitly (identity: id_lokalId) so that this is visible.

What is backdated, and what is not

In the current versions, registration follows valid time within a day (all 1 305: 0–0.7 days). DAGI’s valid time is in practice the time of the edit, not of the decision; backdating appears only through corrections that close earlier versions (the 2024-10-03 case). Registers where facts are routinely backdated — dwellings in BBR, ownership in the land register — will show large gaps; DAGI is the mild case.

Representations: defined, not produced

The data model defines 1:250 000, 1:500 000 and 1:2 000 000 representations of the polling districts (there is no 1:50 000). Since the move to DAGI’s new administration system in July 2026 they are not produced: “Entiteter med underscore _250000, _500000 og _20000000 kan ikke anvendes, da der i DAGIs nye forvaltningssystem ikke findes et system, der generaliserer data” (KDS, Fildownload (DAGI)). On 2026-11-19 the WFS layers and the V3 and V4 file downloads for those scales are empty (0 rows); the Dataforsyningen services that used to deliver them answer 404. The model therefore distinguishes a representation that is defined from one that is delivered, with a date — and here the reason is a change of system, not a gap in our query.

Model 2.0.0 went into production with the new administration system (DAGI3) on 2026-07-02; the migration shows in the register as SystemMigreringDagi3 on 2026-07-01. The generalised classes exist in model 2.0.0 but are not produced, because the new system has no generalisation. The old model-1 services still hold the last generalised polling districts (1 315, from the 2025 local elections) and the church-council polling districts (a class removed in 2.0.0). Both are snapshotted before the services disappear: afstemningsomraade_sgis-000940/2026-03-27/ and menighedsraadsafstemningsomraade_sgis-002183/2026-04-01/. Model 1’s history service gives registration time but no virkningTil — a register history, not a full bitemporal table: one more thing that changed between the models.

None of them is a version in the model’s sense (a release of the dataset): the register has no releases. They belong on the distribution (download version), on the documentation (model version) and in the lineage of the registrations (system migration).

The whole history in one file

Datafordeler’s file download DAGI_V4_Afstemningsomraade_TotalDownload_gpkg_Bitemporal is the register’s complete bitemporal table as a GeoPackage: 29 863 rows for 1 548 districts (1 305 current, 243 ended), 3D multipolygons in EPSG:25832, with the same fields as the services. Each change adds two rows — one that ends the old registration, one that records the old version with its closed validity — so Ejer Bavnehøj has nine rows, matching the GraphQL grid above exactly. The file is a snapshot without saying so: its newest registration is 2026-10-09 10:30, and it was written on 2026-10-11, although the download fetched on 2026-11-19 is numbered 264 and the file inside 230. The registration cutoff, not the download date, is the snapshot date.

Two filters in QGIS answer the bitemporal question without any API:

QuestionFilter on the layer
The districts valid on date D, as known now"registreringtil" IS NULL AND "virkningfra" <= 'D' AND ("virkningtil" IS NULL OR "virkningtil" > 'D')

Districts are created and ended in bursts before elections (May 2022: 10 created, 37 ended; February–March 2024: 23 created, 56 ended; October 2024; August 2026). Of 11 338 versions opened since 2018, 96.5 % were registered within a day of taking effect; 16 more than 30 days later (the longest 393 days, corrections in 2024). Changes from an amended regulation (ændretBekendtgørelse) were registered a median 17.5 days before they took effect — forward-dated, the mirror image of backdating: the register knew of the change before it was true.

Snapshot

A snapshot of the register fixes registration time: the register as it stood at its last registration. On the RUC data share: datasets/afstemningsomraade_sgis-000940/2026-10-09/ — the full bitemporal history as GeoParquet (42 MB against 673 MB as GeoPackage; geometry 2D because every Z was 0, time fields typed as UTC timestamps, sorted by id and time), with a README holding the two QGIS filters and a code list of the business events. Dated by the registration cutoff (2026-10-09 10:30), not by the download (2026-11-19). From now on vector snapshots on the share are GeoParquet by default.
